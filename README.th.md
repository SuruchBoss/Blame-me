# Blame-me

**ให้กรรมการจำลองหาจุดอ่อนในงานก่อน ดีกว่าไปเจอต่อหน้ากรรมการตัวจริง**

[English](README.md)

พรุ่งนี้ต้องนำเสนองาน อาจเป็นโครงงานในวิชา ไอเดียที่ส่งประกวด หรือข้อเสนอให้หัวหน้า เราอ่านมาสามรอบแล้ว ดูไม่มีอะไรผิด เพราะเรารู้ว่าแต่ละส่วนหมายถึงอะไร แต่คนที่ตัดสินพรุ่งนี้ไม่รู้ เขาอ่านเป็นครั้งแรก และอาจมีสักคนเอาตัวเลขสองตัวของเรามาวางคู่กัน แล้วเห็นว่าแผนนี้ไปต่อไม่ได้

Blame-me ทำมาสำหรับคืนนั้น ส่งงานให้มัน พร้อมโจทย์หรือเกณฑ์ถ้ามี มันจะเสนอกรรมการเล็กๆ จากคนที่จะตัดสินงานนี้จริง เช่น อาจารย์ กรรมการประกวด ลูกค้า นักบัญชี เราเปลี่ยนตัวได้ จากนั้นแต่ละคนจะอ่านงานเหมือนเพิ่งเห็นครั้งแรก ไม่เห็นคำอธิบายของเรา แล้วหาจุดอ่อนแบบที่คนทดสอบโปรแกรมหาบั๊ก

สิ่งที่ได้กลับมาคือรายการจุดอ่อน ข้อที่หนักที่สุดอยู่บนสุด แต่ละข้อบอกว่าอยู่ตรงไหนในงาน จะเป็นปัญหาตอนไหน และมีวิธีเช็กง่ายๆ ที่ทำได้ภายในสัปดาห์นี้ มีรายการสั้นๆ ว่าส่วนไหนใช้ได้แล้ว จะได้รู้ว่าอะไรไม่ต้องรื้อ และบอกว่าควรเริ่มจากข้อไหน มันไม่เขียนงานใหม่ให้ ท้ายสุดจะถามว่าอยากให้ช่วยแก้ข้อไหน

ใช้ได้กับทุกคนที่ต้องนำเสนองาน ตั้งแต่นักเรียนที่ไม่มีใครช่วยดูงาน ไปจนถึงคนทำงานที่ต้องเสนอลูกค้า คำที่ใช้จึงตั้งใจให้ง่าย

มีสองโหมด **ปกติ** พูดนิ่งๆ ตรงๆ **แรง** เหมือนหัวหน้าที่เข้มงวดในห้องประชุม ติงานตรงๆ ไม่ติตัวคน และไม่หยาบ ทั้งสองโหมดตั้งใจให้เจอจุดอ่อนชุดเดียวกัน ต่างกันแค่ถ้อยคำ

ถ้า grill-me คือเพื่อนที่ถาม "ทำไม" ซ้ำๆ จนแผนเราชัด blame-me ก็คือกรรมการที่ชี้ลงบนหน้ากระดาษแล้วบอกว่า "ตรงนี้แหละที่พัง"

**สิ่งที่ลองจริงแล้ว** (ผู้เขียนลองเองอย่างละหนึ่งครั้ง กับงานสมมติสองชิ้น วันที่ 2026-11-01 รายละเอียดอยู่ใน[ข้อจำกัดและส่วนที่ยังไม่ได้ทดสอบ](#ข้อจำกัดและส่วนที่ยังไม่ได้ทดสอบ)):

- งานประกวดของนักศึกษา (ข้าวกล่องส่งถึงตึกเรียน) และข้อเสนอธุรกิจ (กาแฟส่งถึงออฟฟิศ) ทั้งสองชิ้นเป็นงานสมมติที่ฝังจุดอ่อนไว้ ทุกรอบกรรมการเจอจุดอ่อนหลักที่ฝังไว้ครบ งานนักศึกษา: ส่งกล่องละ 2 นาที 100 กล่องไม่ทันในพักเที่ยงชั่วโมงเดียว ยอด 100 กล่องต่อวันมีเพื่อนรองรับแค่ 20 คน และเป้ารายเดือนคิด 30 วันทั้งที่ขายแค่วันเรียน ข้อเสนอธุรกิจ: ขายราคานี้แล้วขาดทุนทุกออฟฟิศ ซึ่งจะเห็นก็ต่อเมื่อคูณตัวเลขจากสามหัวข้อเข้าด้วยกัน ผู้เขียนคิดเลขซ้ำทุกตัวในรายงานแล้ว ถูกหมด
- "ส่วนที่ใช้ได้แล้ว" หยิบส่วนที่ตั้งใจเขียนให้ดีขึ้นมาได้ คือการนับคิวโรงอาหารที่นักศึกษาทำเอง และตัวเลขที่คำนวณถูก
- ถ้าไม่ได้ระบุกรรมการ มันเสนอที่นั่งที่เข้ากับนักศึกษา (กรรมการประกวด เพื่อนในคณะที่จะซื้อ คนที่ขายข้าวกล่องอยู่แล้ว) และขอเกณฑ์ให้คะแนน
- พอให้เกณฑ์ประกวดไป กรรมการแต่ละคนให้คะแนนตามเกณฑ์นั้น และคะแนนบวกกันได้ตรง
- วิธีเช็กเป็นสิ่งที่นักศึกษาทำได้จริง เช่น ลองส่งจริง 20 กล่องแล้วจับเวลา เปิดพรีออเดอร์แบบจ่ายก่อนสามวัน นับคิวอีกสี่วัน
- โหมดแรงติงานตรงขึ้น และไม่พูดถึงตัวนักศึกษาเลย
- มันยังพลาด และเก็บไว้ในตัวอย่างตามจริง กฎห้ามพูดเรื่องที่งานไม่ได้บอกเหมือนเป็นความจริง ได้ผลกับรายงานหนึ่งฉบับ แต่อีกสองฉบับยังพลาด ฉบับหนึ่งยังอ่านได้ว่านักศึกษามีเตาใบเดียว อีกฉบับฟันธงว่าใครจ่ายค่ากาแฟในออฟฟิศ ซึ่งข้อเสนอไม่ได้บอก ดู [examples/README.md](examples/README.md)

งานสมมติสองชิ้นกับรายงานห้าฉบับอยู่ใน [examples/](examples/)

**ยังไม่ได้ลอง:** อ่านซ้ำหลังแก้ ใช้ใน Claude.ai หรือแอปแชทอื่น ติดตั้งจาก GitHub และงานจริงของคนอื่นนอกจากผู้เขียน

## ใช้กับงานอะไรได้บ้าง

- ไอเดีย แม้จะมีแค่ย่อหน้าเดียว
- โครงงาน รายงาน และงานนำเสนอในโรงเรียนหรือมหาวิทยาลัย
- งานส่งประกวดและงาน pitch
- แผนธุรกิจ และข้อเสนอให้ลูกค้าหรือหัวหน้า
- Case study และงานที่บริษัทให้ทำตอนสมัครงาน
- เรซูเม่ จดหมายสมัครงาน และใบสมัครทุนหรือมหาวิทยาลัย
- บทความและโพสต์

**ไม่ใช้**กับโค้ดหรือเอกสารออกแบบทางเทคนิค (ใช้ code review แทน) และไม่แตะเรื่องส่วนตัวหรือเรื่องชีวิต เรซูเม่จะถูกอ่านในฐานะงานที่คนอื่นจะตัดสิน ไม่ใช่การตัดสินตัวเรา

## เริ่มใช้

ต้องมี Claude Code

```bash
claude plugin marketplace add SuruchBoss/Blame-me
claude plugin install blame-me@blame-me
```

แล้วเปิด session ใหม่ (สกิลที่ติดตั้งระหว่าง session ยังใช้ใน session เดิมไม่ได้) แล้วพิมพ์

```
/blame-me:blame-me path/to/your-work.md
```

หรือพิมพ์ธรรมดาก็ได้ เช่น "blame ข้อเสนอนี้หน่อย" "หาจุดอ่อนในโครงงานนี้ให้หน่อย" ถ้าถามแบบสบายๆ เช่น "ไอเดียนี้ดีไหม" "ขอคอมเมนต์หน่อย" มันจะถามกลับหนึ่งข้อก่อนว่าอยากได้ความเห็นสั้นๆ หรือให้กรรมการอ่านแบบจริงจัง ถ้าเลือกสั้นๆ จะได้คำตอบธรรมดาสั้นๆ ไม่มีกรรมการ ถ้าอยากได้โหมดแรง เติม `harsh` หรือ `โหมดแรง` (หรือพิมพ์ว่า "ด่าแรงๆ เลย")

```
/blame-me:blame-me โหมดแรง path/to/your-work.md
```

ถ้าไม่ใช้ marketplace ให้คัดลอกโฟลเดอร์ `plugins/blame-me/skills/blame-me/` ไปไว้ที่ `~/.claude/skills/` หรือ `.claude/skills/` ของโปรเจกต์

## รีวิวหนึ่งรอบเป็นยังไง

1. **ดูก่อนว่าส่งอะไรมา** โค้ดและเรื่องส่วนตัวจะถูกปฏิเสธ
2. **เสนอกรรมการ** ค่าเริ่มต้นสามคน มากสุดห้าคน แต่ละคนบอกว่าเป็นใคร ดูอะไรก่อน และคำถามข้อเดียวที่ตัดสินว่าเขาจะตอบรับไหม เราเก็บไว้หรือเปลี่ยนก็ได้ และมันจะถามว่างานนี้ส่งให้ใคร มีโจทย์หรือเกณฑ์ไหม
3. **แต่ละคนอ่านเอง** เห็นแค่ตัวงาน โจทย์ และบทบาทของตัวเอง ไม่เห็นคำอธิบายของเรา ไม่เห็นความเห็นของกันและกัน ใน Claude Code แต่ละคนเป็นผู้ช่วยแยกกัน ถ้าทำแบบนั้นไม่ได้ จะมีโมเดลเดียวสลับเล่นทีละบทบาท และรายงานจะบอกไว้
4. **รวมผลแล้วตรวจซ้ำ** จุดอ่อนที่หลายคนพูดตรงกันจะขึ้นไปอยู่สูง ทุกตัวเลขถูกคิดใหม่ ข้อที่ไม่ได้ชี้ไปที่ตรงไหนในงาน ข้อที่พูดกับงานไหนก็ได้ และข้อที่งานตอบไว้แล้ว จะถูกตัดทิ้ง ส่วนเรื่องที่เช็กจากตัวงานไม่ได้จะไปอยู่ใน "ต้องเช็กเพิ่ม" แทนที่จะถูกพูดเหมือนเป็นความจริง
5. **ได้รายงาน** ผ่านหรือไม่ผ่านจากกรรมการแต่ละคนพร้อมเหตุผล (ให้คะแนนเฉพาะเมื่อเรามีเกณฑ์) จุดอ่อน ส่วนที่ใช้ได้แล้ว เรื่องที่ต้องเช็กเพิ่ม ควรเริ่มจากตรงไหน และบรรทัดสุดท้าย "จะให้ช่วยแก้ข้อไหนไหม"
6. **อ่านซ้ำ** แก้งานแล้ว ส่งเวอร์ชันใหม่กับรายงานเดิมไป มันจะบอกว่าข้อเดิมแก้แล้ว แก้บางส่วน หรือยังไม่ได้แก้ แล้วอ่านเวอร์ชันใหม่เหมือนเพิ่งเห็น เพื่อหาสิ่งที่การแก้ทำพังเพิ่ม

จุดอ่อนมีสามระดับ **ต้องแก้ก่อนไปต่อ** (ถ้าจริง งานล้มทั้งชิ้น) **ควรแก้** (คนอ่านจะไม่รับถ้าไม่แก้) และ **แก้ก็ดี** (ทำให้งานอ่อนลง แต่ไม่ถึงกับล้ม)

จุดอ่อนแต่ละข้อหน้าตาแบบนี้ (ข้อ 1 ของ [examples/student-report-normal.th.md](examples/student-report-normal.th.md) ไม่ได้แก้)

```
1. ส่ง 100 กล่องไม่ทันในหนึ่งชั่วโมง (ต้องแก้ก่อนไปต่อ, 3/3)
- ที่ในงาน: "ส่งกล่องละประมาณ 2 นาที", "ช่วง 12:00 ถึง 13:00", "ขายวันละ 100 กล่อง"
- คำนวณ: 100 × 2 = 200 นาที แต่มีเวลา 60 นาที ส่งคนเดียวได้ 30 กล่อง สองคนพร้อมกันได้ราว 60 กล่อง
  ถ้าแบ่งกันส่ง 100 กล่อง ก็ยังคนละ 100 นาที
- พังเมื่อ: ยอดสั่งเกิน 30 ถึง 60 กล่อง ลูกค้าท้ายแถวได้ข้าวตอน 13:00 หรือหลังหมดพัก
- เช็กเร็วๆ: ส่งจริง 20 กล่องไปตึกเรียนจริงตอนเที่ยง จับเวลาต่อกล่อง แล้วคูณใหม่
```

## ปกติกับแรง เทียบกัน

จุดอ่อนข้อเดียวกันของไอเดียสมมติ แอปจับคู่ติวหนังสือในโรงเรียน ครั้งละ 20 บาท ที่มีหลักฐานแค่ "เพื่อนบอกว่าไอเดียดี"

> **ปกติ:** รายได้ทั้งหัวข้อขึ้นอยู่กับนักเรียน 1,200 คนที่ใช้ทุกสัปดาห์ หลักฐานมีแค่ว่าเพื่อนชอบไอเดีย การชอบไอเดียไม่เหมือนกับยอมจ่าย 20 บาททุกสัปดาห์

> **แรง:** ตัวเลขทุกตัวในหัวข้อรายได้ตั้งอยู่บน "เพื่อนบอกว่าไอเดียดี" ประโยคนี้ไม่รอดคำถามแรกของกรรมการ เพื่อนพูดดีด้วยไม่ได้แปลว่าจะมีคนซื้อ

ตัวอย่างเพิ่มเติมทั้งสองภาษาอยู่ที่ [references/tone.md](plugins/blame-me/skills/blame-me/references/tone.md)

## ในแพ็กเกจมีอะไร

```
plugins/blame-me/skills/blame-me/
  SKILL.md              ทุกอย่างที่ต้องใช้ในการรีวิวหนึ่งรอบ
  references/
    panel.md            เลือกกรรมการ สำหรับงานนักเรียนและงานคนทำงาน
    angles.md           จุดที่ควรดู และอะไรที่ไม่นับเป็นจุดอ่อน
    report.md           รูปแบบรายงาน ไทยและอังกฤษ และคำง่ายที่ใช้แทนศัพท์ยาก
    tone.md             โหมดปกติและโหมดแรง พร้อมตัวอย่าง
    reread.md           อ่านซ้ำหลังแก้
examples/               งานสมมติสองชิ้น และรายงานที่ได้จากการรันจริง
```

`SKILL.md` มีกฎครบในตัว ถ้าเครื่องมือเปิดไฟล์อื่นไม่ได้ ก็ยังรีวิวได้

## ข้อจำกัดและส่วนที่ยังไม่ได้ทดสอบ

ทุกรอบด้านล่าง: Claude Code 2.1.316 รันแบบ headless (`claude -p`) บน Linux วันที่ 2026-11-01 โหลด plugin ด้วย `--plugin-dir` ใช้โมเดลค่าเริ่มต้น อย่างละหนึ่งรอบ ค่าใช้จ่ายเป็นตัวเลขที่ CLI รายงานของรอบนั้น

| ส่วน | สถานะ |
|---|---|
| เสนอกรรมการแล้วหยุดรอ | ลองกับเวอร์ชันนี้หนึ่งครั้ง (งานนักศึกษา) เสนอที่นั่งที่เข้ากับนักศึกษา ขอเกณฑ์ แล้วหยุดรอ (ราว $0.08) ร่างก่อนหน้าก็ทำแบบเดียวกันกับข้อเสนอธุรกิจ |
| กรรมการแยกเป็นผู้ช่วย | ลองห้ารอบ เปิดผู้ช่วยสามตัวพร้อมกันทุกครั้ง (ราว $0.5 ถึง $0.8 ต่อรอบ) |
| โมเดลเดียวสลับเล่นทีละบทบาท | ลองหนึ่งครั้ง โดยปิดเครื่องมือผู้ช่วย และให้รายงานเป็นภาษาอังกฤษ รายงานบอกว่าใช้วิธีไหน (ราว $0.1) |
| ให้คะแนนตามเกณฑ์ | ลองสองครั้งกับเกณฑ์ประกวด คะแนนแยกตามหัวข้อของเกณฑ์ และบวกกันได้ตรง |
| โหมดปกติกับโหมดแรงเจอเรื่องเดียวกัน | ส่วนใหญ่ใช่ ในงานนักศึกษาสองรอบ จุดอ่อนหลักตรงกัน แต่บางข้อจัดระดับต่างกัน |
| คำง่าย | รอบแรกมีคำยากหลุดมาบ้าง ("helper" "ค่าเสื่อม" "moot") หลังเพิ่มกฎให้ไล่หาคำยาก รายงานสามฉบับที่รันใหม่ไม่มีเลย |
| ภาษาไทยที่ไม่ระบุเพศ | ก่อนเพิ่มกฎ มีรอบแรกๆ หนึ่งรอบที่ใช้ "ผม" หลังเพิ่มกฎ ไม่มีรายงานไหนใช้อีก |
| ข้อความระหว่างรอ ใช้ภาษาเดียวกับงาน | บางข้อความในรอบภาษาไทยออกมาเป็นภาษาอังกฤษ เพิ่มกฎทีหลังแล้ว ยังไม่ได้ลอง |
| ความแม่นยำ | ตัวเลขทุกตัวที่ผู้เขียนตรวจถูกหมด แต่ยังมีบางข้อที่พูดเกินกว่าที่งานบอก แม้จะเพิ่มกฎห้ามแล้ว (ดู [examples/README.md](examples/README.md)) อ่านข้อติก่อนเชื่อ |
| อ่านซ้ำหลังแก้ | ยังไม่ได้ลอง |
| ถามแบบสบายๆ ("ไอเดียนี้ดีไหม") | ลองกับไอเดียภาษาไทยหนึ่งชิ้นและอังกฤษหนึ่งชิ้น ใน Claude Code 2.1.316 ถามสบายๆ แล้วสกิลถูกเรียกเองทุกครั้ง ถามคำถามเดียวในภาษาของผู้ใช้แล้วหยุดรอ (6 รอบ) ตอบว่า "สั้นๆ" ได้คำตอบธรรมดา ไม่มีกรรมการ (ไทย 1 รอบ) ตอบว่า "จริงจัง" ไปเสนอกรรมการ (ไทย 1 อังกฤษ 2) รอบอังกฤษแรกเขียน "tell me" กับ "I'll run it" หลังเพิ่มกฎ รอบที่รันใหม่ไม่มีแล้ว ตอนเสนอกรรมการถามกลับได้ไม่เกินสองข้อ (ใครอ่านงานนี้ และมีเกณฑ์ไหม) สี่รอบหลังเขียนกฎนี้ (ไทยและอังกฤษ) ถามหนึ่งหรือสองข้อ ถ้าเรียกตั้งใจ (`/blame-me:blame-me` ทั้งแบบมีและไม่มี "ด่าเลย") ข้ามคำถามนี้ (2 รอบ) ราว $0.06 ถึง $0.15 ต่อครั้ง ภาษาอื่นยังไม่ได้ลอง |
